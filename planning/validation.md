# Requirement validation

Reviewed at the user’s request against the current source, test assertions and selected saved deliverables. One row corresponds to each R ID in [spec.md](spec.md); Q IDs are open questions, not additional requirements. These are evidence-based agent findings, not facilitator acceptance.

Scope: functional checks use saved mock responses or fake HTTP transports, with network and API_KEY access prohibited by the test harness. They establish the reviewed corpus and implementation behavior, not live-provider availability, live extraction accuracy, arbitrary attack recognition or multi-host operation. No release actions were performed for this review.

Fresh reproduction: `env -u API_KEY .venv/bin/python -m unittest discover -s tests -v > verification/validation-test-run.txt 2>&1` — **43 tests passed** on Python 3.12.3. Each test citation below links both its assertions and its passing line in that fresh log. The existing [planning/test-run.txt](test-run.txt) was preserved: it records 20 tests with 14 errors caused by missing jsonschema. That failed run is not counted as passing evidence.

Independent saved-artifact inspection is recorded in [validation-artifact-checks.json](../verification/validation-artifact-checks.json): 21 schema-valid objects, source hashes, exact quotes and linked queue records; 252/252 literal scalar comparisons against frozen expectations. Branch/capture observations and the stale test-log reference are recorded in [validation-release-checks.json](../verification/validation-release-checks.json).
